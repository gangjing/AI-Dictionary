# AI Dictionary — Windows / macOS 本地 AI 词典产品需求文档

**版本：** v1.0  |  **日期：** 2026-11-12  |  **状态：** 开发基线 / 待验证技术假设  |  **产品代号：** AI Dictionary（暂定）

> 产品目标：打造一个参考有道词典核心使用体验、以腾讯 Hy-MT2 为主翻译引擎、跨 Windows 和 macOS 的本地优先桌面词典。重点覆盖查词、划词、截图 OCR、全文翻译、发音、例句及生词本；兼顾离线、隐私和低资源占用。本 PRD 用于指导设计、技术选型、研发拆分与验收，不代表已经完成兼容性和速度实测。

## 0. 开发执行摘要

**目标产品：** Windows/macOS 双平台、基于 Hy-MT2 的本地 AI 词典。

**V1.0 交付范围：**

1. 输入查词：中英释义、音标、词性、例句、单词变形。
2. 全局划词：在浏览器、Office、PDF 等应用中使用快捷键查词或翻译。
3. 截图翻译：区域截图、本地 OCR、文本编辑及翻译。
4. AI 翻译：Hy-MT2 本地推理，中英互译、长文分段、复制和取消。
5. 词汇学习：生词本、查询历史、收藏、备注和 CSV 导出。
6. 系统集成：快捷键、系统托盘、开机启动设置、模型管理。
7. 隐私保护：离线使用、最小权限、不默认上传内容、不强制注册账户。

**技术基线：** Tauri 2 + React + TypeScript + Rust；llama.cpp 独立推理进程；Hy-MT2-1.8B Q4_K_M 默认模型；SQLite 词典与用户数据库；macOS Vision / Windows OCR。

**功能优先级：** P0 包含上述核心功能和双平台安装包。P1 扩展 7B 模型、术语表、翻译风格、结构保护和生词复习。P2 才考虑在线服务、同步与进一步插件化。

**性能目标：** 基础词典查询 p95 小于 150ms；选词后浮层出现 p95 小于 350ms（不含 AI 生成时间）；翻译结果异步输出并允许取消。AI 性能须在实际目标设备上验证。

**交付计划：** 先验证模型运行、系统取词、OCR 和词典许可证；然后开发核心 UI、翻译、悬浮卡与生词本；最后进行兼容性、权限、安全及安装包测试。

**预计开发周期：** 单人全职约 8–11 周，属于规划估算，具体取决于跨应用取词及模型性能验证结果。

**发布标准：** Windows x64、Mac Apple Silicon、Mac Intel 至少各有一套通过安装、查词、翻译、划词、OCR 的完整测试；无阻断性错误；模型及词典数据授权明确。

## 1. 产品概述与决策摘要

### 1.1 产品愿景

让用户在浏览器、PDF、Word、邮件和即时通讯等桌面软件中，不离开当前工作流就能快速理解陌生单词、短句和长文本。基础词典查询应瞬时、可离线；复杂句子及段落翻译由 Hy-MT2 本地处理；屏幕上无法选中的文本可通过 OCR 识别。

### 1.2 关键产品决策

| 项目 | v1.0 决策 | 理由 |
|---|---|---|
| 操作系统 | Windows 11 x64；macOS 13+，分别发布 Apple Silicon arm64 与 Intel x64 包 | 覆盖主流桌面和现有 Intel Mac；最终最低版本以构建测试为准 |
| 桌面框架 | Tauri 2 + React + TypeScript + Rust | 共享 UI 和业务逻辑，同时允许系统原生能力 |
| 翻译模型 | Hy-MT2-1.8B-GGUF Q4_K_M 默认；7B Q4 可选 | 1.8B Q4 文件约 1.13GB；7B Q4 约 4.62GB，适配不同机器 |
| 推理后端 | llama.cpp 构建的受控本地 sidecar / 进程，按 OS/CPU 架构分发 | 不强制安装 Python、CUDA 或 Docker；隔离故障与升级 |
| 基础词典 | SQLite/FTS5 + 有授权的词典数据（首选 WordNet 英文语义 + 可合法再分发中英词表） | 结构化释义可靠、低延迟、成本低 |
| OCR | macOS Vision + Windows.Media.Ocr（可替换适配层） | 系统原生优先，离线处理 |
| 发音 | 词典 IPA（若数据源提供）+ OS 离线 TTS；可升级独立语音资源 | Hy-MT2 不产生标准音标或语音 |
| 数据策略 | 单机本地优先；无账户、无遥测、无云端依赖 | 最大化隐私；降低开发复杂度 |
| 模型分发 | 安装包不内置大模型；初次引导自愿下载、SHA256 校验、失败续传 | 安装包保持轻量，用户可控制存储 |
| 首发边界 | 中英双向最佳体验，其余 Hy-MT2 支持的语种逐步开放 | 词典数据、OCR、TTS 的多语种覆盖不同于翻译模型 |

### 1.3 重要技术事实与边界

Hy-MT2 官方列出 1.8B、7B 和 30B-A3B 三档，以及 GGUF/FP8 等发布形式；官方称可支持多语言翻译，并给出术语约束、风格、结构化数据等指令例子。仓库 LICENSE.txt 标注 Apache-2.0。1.8B 的 Q4_K_M 文件约 1.13GB，7B Q4_K_M 约 4.62GB。官方宣传的 440MB 1.25-bit 极限量化版本需要特殊 STQ 内核；截至本稿核验，该相关 llama.cpp PR 未合并，因此不作为 v1 的交付前置依赖。模型文件大小不等于运行时峰值内存占用，需计算 KV cache、计算缓冲、OCR 和 UI 占用。模型宣称的相对速度与质量也不能直接套用到具体个人电脑。

## 2. 用户、场景与市场定位

### 2.1 核心用户

- **P1 中英文办公用户（主用户）**：频繁阅读英文邮件、技术文档、网页和 PDF，需要高质量中英互译，重视效率和隐私。
- **P2 学生及语言学习者**：查词义、音标、词性、例句，积累生词并复习，要求低认知负担。
- **P3 技术用户/开发者**：阅读代码注释、GitHub 文档、API 文档，需要术语一致、避免改动代码、变量和占位符。
- **P4 无法联网/不便上传文本用户**：需要本地 OCR 和翻译，明确信息不会上传。

### 2.2 核心任务（Jobs to Be Done）

- 看见陌生英文单词，3 次操作以内获取释义、音标和发音。
- 阅读网页或 PDF 时选中句子，按快捷键查看符合上下文的中文翻译，不切换应用。
- 截图识别图片上的外文并直接翻译，保留可复制文本。
- 把英文工作邮件贴入主窗口，翻译成中文，或将中文译成专业自然的英文。
- 将经常查询的单词加入生词本，离线查看并导出 CSV。

### 2.3 对标策略及差异化

参考有道桌面版的屏幕取词、划词释义、全文翻译、音标发音和例句等交互模式，但不复制其商标、代码、界面素材、词库或受版权保护的内容。差异化是：默认本地推理、模型可切换、隐私可解释、极简无广告、可审计的开放数据来源、低干扰的全局快捷键。

### 2.4 范围内与范围外

**v1 范围内：** 输入查词、中英词典卡、发音、全局快捷键划词、可选“选中即显示翻译图标”、截图 OCR、短文翻译、历史记录、生词本、模型下载/管理、离线设置、Windows/macOS 安装与卸载。

**v1 范围外：** 系统输入法、浏览器扩展、PDF/Word 原格式批量翻译、视频字幕实时翻译、语音实时同传、拍照查物、帐号同步、移动端、AI 对话老师、在线专有词典抓取、云端翻译服务、单词社交和广告。

## 3. 目标与衡量标准

### 3.1 成功定义（内测准入指标；不是已验证性能）

| 维度 | MVP 目标 | 测量方法 |
|---|---|---|
| 查词效率 | 本地词典查询 p95 < 150ms（不含首次磁盘加载） | 1,000 次重复查询，测 UI 可见结果 |
| 快捷操作 | 选中文字后触发到弹窗出现 p95 < 350ms（不含 AI 完整译文） | Windows/macOS 多应用自动化计时 |
| 翻译反馈 | 有加载状态和取消操作；首个流式结果 p95 < 5s（指定基准机、短句），不作所有设备承诺 | 需先确定基准设备及实测门槛 |
| OCR | 清晰截图中英文字识别准确率 >= 95%（字符级，内测标准集） | 500 张固定样本 |
| 正确性 | 中英翻译人工盲评 >= 4/5 占比 80%；关键数字/专有名词错误率 < 2% | 200 组工作/学习语料 + 关键实体核查 |
| 稳定性 | 24 小时桌面驻留不崩溃；异常模型进程可恢复 | 长稳和故障注入 |
| 离线能力 | 初次下载后查词、翻译、OCR、收藏在断网状态可执行 | 网络切断 E2E |
| 安全与隐私 | 无隐式上传；敏感输入不落盘（私密模式）；下载可校验 | 流量审计、文件审计 |

### 3.2 北极星指标

**每周有效查询次数（Successful Lookups per Weekly Active User）**。有效查询定义：结果成功展示且用户未收到错误；分别计入字词、短句翻译与 OCR 任务。个人版不默认采集遥测，以可选本地统计页观察指标。

## 4. 信息架构与导航

主窗口侧边栏：**查词 / 翻译 / 截图 / 生词本 / 历史 / 设置**。屏幕右下角（或靠近选区）提供轻量浮层。托盘菜单：打开主窗口、翻译剪贴板（显式点击）、截图翻译、暂停划词、加载/卸载模型、退出。

### 4.1 窗口体系

| 窗口 | 主要内容 | 行为 |
|---|---|---|
| 主窗口 | 全局搜索、词条详情、翻译文本框、生词本 | 记住大小和位置；支持拖放文本 |
| 划词悬浮卡 | 简短释义或句子翻译、发音、收藏、复制、展开 | 不抢焦点优先；Esc 关闭；避开屏幕边缘和遮挡 |

| 首次启动向导 | 权限、词典、模型下载 | 可跳过模型，先用纯词典；不强制注册 |

### 4.2 最小线框（信息结构）

主窗口：顶部「搜索单词或粘贴文本」；左栏导航；右侧内容区。词条卡由单词标题、英/美发音、收藏按钮、分词性释义、变形、例句和“用 AI 翻译选中文本”组成。翻译页为左右两个可调整宽度的文本区：原文、译文，下方提供复制、互换语种、术语表和保存历史。

浮层：上行显示源语言 → 目标语言、模式、关闭；中间展示结果；下行显示「复制 | 发音 | 收藏 | 展开」。不展示广告和多余推荐。

## 6. 核心功能详细规格

### 6.1 F-001 / F-002 查词

**入口：** 主窗口搜索框、浮层文本、历史、生词本。用户输入 `running`，通过词形还原优先关联 `run`；若词条存在，按词性展示 1~3 个主要义项及“更多”展开；未命中时可建议拼写相近项、或允许仅执行 AI 翻译。

**规则：** 只输入一个单词/固定短语时优先走词典查询；长度超过阈值、包含句子终止符或多行文本时优先走翻译；用户可手动强制切换。字典中的 IPA、例句、释义必须附带对应可追溯数据源。中文/英文空格、大小写及 Unicode 正规化应一致。

**异常：** 未下载词典包、离线且数据缺失、输入为空、超长输入、控制字符，应以状态提示取代崩溃。单词的多义词不能将模型生成的单一翻译伪装为权威完整释义。

### 6.2 F-003 发音与音标

词条标题下分别展示美式/英式音标（仅在有可靠数据时显示）。播放策略：优先合法授权的离线音频；否则使用 Windows SAPI/系统 TTS 或 macOS NSSpeechSynthesizer，UI 明示“系统语音”。缺乏美/英音区分时不伪造。播放前可停止当前音频，支持设置语速，断网可用，设备无语音资源时给出安装提示。

### 6.3 F-004 / F-005 全局划词

默认快捷键建议 Windows `Ctrl+Alt+T`，macOS `Option+Command+T`（可配置，冲突时引导修改）。触发流程：捕捉当前前台应用及选择文本；首选 UI Automation (Windows) / Accessibility API (macOS)；如不可用，在用户明确启用“复制回退”后执行保存剪贴板→模拟复制→读取→尽量原样恢复。不得在密码输入框、受保护应用或剪贴板格式恢复不可保证时偷偷读取。选中长度建议上限 5,000 字符，超出则转主窗口并提示。

**弹窗策略：** 单词展示词条，句段展示流式译文；浮层靠近鼠标但不覆盖选中区域，右键复制内容，Esc 关闭，点击其他区域消失（设置可关闭）。应记录“当前来源应用”和任务 ID，防止旧任务结果覆盖新任务。

**限制披露：** 部分 PDF、Electron 应用、远程桌面、管理员权限窗口、游戏和安全输入框可能无法可靠提取；失败后给出复制粘贴方案。macOS 需辅助功能授权；不要求永久监听剪贴板。

### 6.4 F-007 翻译

默认方向：自动检测中英并将英文译中文、中文译英文。下拉可显式指定语言对（多语言扩展先只保证模型输出，不承诺全部词典支持）。模型提示词使用官方推荐的自然语言翻译模式，明确“只输出翻译结果”，并提供可选术语表和风格。不同版本须记录提示词版本，避免回归难以定位。

**内容处理：** 保留换行、列表、数字、URL、邮箱、专有名词及 Markdown 代码段；长文分段，保持源段与译段 ID 对齐。未通过格式校验时提示警告，可人工编辑译文；不要静默丢段。超过上下文或单次输入限制时自动拆分、并行数默认 1、可取消任务。模型回答中可能有未按指令输出解释的情况，做基本后处理而非机械截断句意。

**用户交互：** 点击“翻译”后展示状态、逐字/按段输出（视底层能力）；停止生成；复制、重试、交换语言、保存/不保存历史。网络断开不影响本地模型。

### 6.5 F-008 截图 OCR

用户点击截图按钮或快捷键，进入全屏选区层 → 拖框 → 本地 OCR → 识别文本可编辑 → 翻译/复制。多显示器采用各屏实际坐标和缩放比；支持 100%~200% 缩放及 Retina；屏幕遮罩不能在截图中反复自我捕获。macOS 需屏幕录制权限，Windows 需支持的截图 API；系统禁止捕获的内容不绕过保护。

MVP 先支持中英截图，复杂版式、竖排、手写、低分辨率或 DRM 页面可能不准确。OCR 结果若低置信度，允许用户直接修改再翻译；默认不保存图片。

### 6.6 F-009 / F-010 生词本与历史

本地 SQLite 保存词条 key、源语言、目标语言、释义快照/来源版本、收藏时间、自定义备注、标签；同词+同语言对去重，允许用户选择是否保存不同语境示例。历史默认仅本机保存 90 天或最多 3,000 条，可在设置更改/关闭；私密模式不落盘、不记录选中文本、不加入系统剪贴板历史（除非用户主动复制）。支持 CSV 导出，用户删除后不保留隐藏分析副本。

### 6.7 F-011 模型下载与管理

首次运行进入“基础词典可直接使用 / 下载 AI 模型启用离线翻译”选择页。展示模型名称、版本、文件大小、推荐内存、磁盘剩余量、下载来源、许可证、使用提示。下载应为 HTTPS、支持进度、暂停/取消、可恢复、不完整文件 `.part`、校验 SHA256、原子替换。用户可设模型存储路径、卸载或回滚；空间不足/下载失败时保留查词功能。

首次版本下载 1.8B Q4，7B 在高级设置按需下载。1.25-bit 模型仅在 STQ 依赖具备稳定可重复构建与质量回归测试后标记为实验性。运行时应限制 CPU 线程及模型任务并发数；空闲释放策略用户可配置。

### 6.8 F-012 权限、设置、系统集成

首次使用仅在功能发生时申请对应权限，而不是启动即索取所有权限。提供一键暂停划词、启动时不加载模型、开机启动关闭默认、浅色/深色跟随系统、窗口置顶可选、热键冲突检查、自定义翻译目标语。托盘退出与关闭窗口最小化应区别显示，防止用户误以为退出实际仍常驻。

## 8. 模型选型与性能基准

| 模型 | 文件体积（官方发布页面） | 建议用途 | v1 状态 |
|---|---|---|---|
| Hy-MT2-1.8B GGUF Q4_K_M | 约 1.13GB | 默认，本地快速翻译 | P0 |
| Hy-MT2-1.8B GGUF Q6_K | 约 1.47GB | 追求较高精度、仍需低资源 | P1 |
| Hy-MT2-1.8B GGUF Q8_0 | 约 1.91GB | 较高精度对照基线 | P1 测试用途 |
| Hy-MT2-7B GGUF Q4_K_M | 约 4.62GB | 内存充足机器可选高质量 | P1 |
| Hy-MT2-1.8B 1.25-bit GGUF | 官方称约 440MB | 极低存储实验 | P2 技术预研，依赖 STQ 兼容 |
| Hy-MT2-30B-A3B | 大模型 | 暂不考虑普通笔记本默认本地部署 | 不在 v1 范围 |

**设备分级建议（工程预设，须实测修正）：** 8GB 内存机器优先 1.8B Q4，限制并行及上下文；16GB 可考虑 Q4/Q6；32GB 及以上可试 7B Q4。不要根据磁盘文件大小推断内存够用。Mac Apple Silicon 优先 Metal 后端；Intel Mac 优先 CPU，若 Metal 能力适配且经过 QA 才启用；Windows 有兼容 GPU 时可通过独立后端配置启用，否则回退 CPU。界面必须能显示实际后端与模型。

**基准计划：** Windows Intel CPU-only、Windows NVIDIA GPU、Mac M1 8GB、Mac Intel x64 16GB、Mac Apple Silicon 16GB 五组设备；每组测启动耗时、峰值 RSS、闲置内存、首 token 延迟、tokens/s、100/500/2,000 字翻译耗时、功耗/热量及质量差异；记录模型 SHA、llama.cpp commit、量化格式、线程、上下文、温度、负载。若低端设备速度无法接受，应降级为“本地词典模式”，不能谎称快速 AI 翻译。

## 9. 技术架构

### 9.1 分层结构

```
Windows/macOS 桌面层
  ├─ Tauri 2 / React 主窗口、浮层、托盘、热键
  └─ Rust application orchestrator（会话、权限、队列、事件）
        ├─ Selection Adapter：Win UI Automation / macOS Accessibility
        ├─ Capture & OCR：WinRT OCR / Apple Vision
        ├─ Dictionary Service：SQLite + FTS5 + 形态还原/搜索
        ├─ Speech Adapter：Windows SAPI / macOS 系统 TTS
        ├─ History & Wordbook Repository：本地 SQLite
        ├─ Model Manager：版本、下载、校验、删除
        └─ Translation Service：隔离的 llama.cpp sidecar
              └─ Hy-MT2 GGUF 模型（Q4 默认，可切换）
```

### 9.2 模块接口约定

- `lookupWord(text, locale, context?) -> DictionaryEntry | NotFound`：离线词典查询，返回 `source_id`。
- `translate({text, sourceLang, targetLang, style?, glossary?, preserveFormat?, requestId}) -> async chunks`：开始翻译并支持 `cancel(requestId)`。
- `readSelectedText({appId, method}) -> SelectionResult`：取当前选区，携带来源与权限状态，失败回退不越权。
- `captureRegion(rect) -> imageBytes` + `recognizeText(imageBytes, languages) -> OCRLine[]`：截图及 OCR；默认不将图片写入临时永久文件。
- `saveWord(entryId, note?, tags?)`、`searchWords(query)`、`deleteHistory(filter)`：本地持久化。
- `listModels / downloadModel / verifyModel / activateModel / removeModel`：模型生命周期。

### 9.3 进程、并发与资源控制

翻译在单独进程执行，主 UI 不因推理阻塞。模型任务队列默认 1 个活动任务，后续新任务可抢占旧划词请求；用户主动开始的长文翻译优先级可高于自动悬浮查询，且有停止按钮。超时、OOM、sidecar 崩溃后自动熔断并展示错误；连续 3 次异常时禁用自动加载并建议改用轻量模型。空闲 5~15 分钟可卸载模型（用户可选），但不能影响基础词典查询。

安全约束：sidecar 默认仅与应用私有 IPC 通道通信；若采用 loopback HTTP，则绑定 127.0.0.1、随机端口与访问令牌，不公开监听 0.0.0.0。模型文件不可执行，模型来源必须 allowlist + 完整性校验；外部文本永远视为不可信数据，不把其中指令解释为软件操作命令。

### 9.4 本地数据模型（建议）

```sql
CREATE TABLE dictionary_entries (
  id TEXT PRIMARY KEY,
  lemma TEXT NOT NULL,
  lang TEXT NOT NULL,
  ipa_uk TEXT,
  ipa_us TEXT,
  senses_json TEXT NOT NULL,
  examples_json TEXT,
  source_id TEXT NOT NULL,
  source_version TEXT NOT NULL
);
CREATE VIRTUAL TABLE dictionary_fts USING fts5(lemma, content='dictionary_entries', content_rowid='rowid');
CREATE TABLE saved_words (
  id TEXT PRIMARY KEY, entry_id TEXT, source_text TEXT NOT NULL,
  source_lang TEXT, target_lang TEXT, note TEXT, tags_json TEXT,
  saved_at TEXT NOT NULL, updated_at TEXT NOT NULL,
  UNIQUE(source_text, source_lang, target_lang)
);
CREATE TABLE query_history (
  id TEXT PRIMARY KEY, kind TEXT NOT NULL, input_text TEXT,
  result_excerpt TEXT, source_lang TEXT, target_lang TEXT,
  created_at TEXT NOT NULL
);
CREATE TABLE model_registry (
  id TEXT PRIMARY KEY, model_name TEXT NOT NULL, quant TEXT,
  file_path TEXT NOT NULL, sha256 TEXT NOT NULL, size_bytes INTEGER,
  status TEXT NOT NULL, installed_at TEXT
);
```

数据结构为逻辑草案，具体 SQL 实施时需处理 FTS5 rowid 同步、迁移版本、敏感历史存储策略及删除级联；词典数据包与用户库应分文件，防止升级覆盖个人生词。

## 11. 非功能性要求

**兼容性：** Windows 11 x64（后续可扩展 Win10）、macOS Intel x64 和 Apple Silicon arm64；具备签名的 Windows MSI/NSIS 与 macOS DMG/PKG 发布流程。macOS 公证/notarization、Windows 签名/SmartScreen 信誉是公开分发前必备任务，内部自用可先采用开发签名但会有系统警告。

**响应性：** 主线程不得执行模型推理或 OCR。输入防抖 80~120ms。查词缓存 LRU；模型加载进度、取消状态清晰可见。

**资源：** 无模型运行时轻量常驻；模型加载时展示明确内存占用，并允许一键卸载。低电量模式/电池供电时可降低线程数或暂停自动翻译。

**隐私：** 不默认读取剪贴板；不启动全局键盘记录；不上传选中文字、截图或历史；用户显式复制时才写入剪贴板；私密模式禁止查询入库和自动截图缓存；设置页面列出本地路径和全部数据删除入口。

**安全：** 权限最小化、模型和更新签名/哈希、依赖漏洞检查、模型端口本地限制、外部文本长度限制、文件路径清理。对 OCR 图片和翻译原文可配置在日志中完全脱敏。

**可维护性：** 翻译核心、词典数据、UI、OCR、系统适配器与模型下载模块各自独立，可做单元测试。日志附 `requestId`, `module`, `elapsedMs`, `errorCode`，不包含文本正文。

## 12. 词典数据与版权合规

1. **禁止直接爬取或复制有道词典版权词条、例句、发音及 UI 素材。** 对标功能不等于拥有数据授权。
2. 英文语义词汇网络可评估 Princeton WordNet 3.0（有独立许可证，要求保留声明）；它不能单独满足中英双向释义、IPA、真实例句的全部需求。
3. 中英词条、音标、例句可评估可合法商用/再分发的开源数据集或自建内容。Wiktionary 衍生数据的署名、相同方式共享及来源追踪义务需逐项验证，不应与闭源专有词库混合发布而忽略许可。
4. 对每种资源记录 `source_id`、版本、许可协议、署名要求、数据清洗流程及再分发权；若无法证明授权，则不进入发布包。
5. Hy-MT2 仓库标注 Apache-2.0；发布时同时核对各 Hugging Face 模型仓库许可证及实际所捆绑模型、推理引擎、词库、TTS 和图标素材的授权。不得暗示腾讯或有道官方背书。

## 14. 质量验证与验收用例

### 14.1 功能验收（代表性 Gherkin 风格）

- **AC-01** Given 已安装词库、断网，When 搜索 `abandon`，Then 150ms p95 内展示可用词条释义（按基准样本测），无网络请求。
- **AC-02** Given 在 Chrome 选中一段英文，When 按翻译快捷键，Then 显示当前选中文本结果；新请求出现后旧翻译不得覆盖新结果。
- **AC-03** Given 在系统安全输入框，When 按热键，Then 不读取密码，不保存记录，并给出不支持提示。
- **AC-04** Given 已授权截图，When 框选两行中英混排文本，Then OCR 展示可编辑识别结果，手动确认后进行翻译。
- **AC-05** Given 安装 AI 模型且断网，When 翻译中文段落，Then 成功得到英文译文；没有未经同意的外部网络调用。
- **AC-06** Given 磁盘不足或下载被中断，When 恢复应用，Then 用户可以续传或取消；字典查询仍正常工作。
- **AC-07** Given 用户处于私密模式，When 查询/划词/OCR，Then SQLite 历史中没有新增记录，关闭后临时缓存删除。
- **AC-08** Given 已收藏 `bank` 并添加备注，When 再次收藏相同语言对，Then 不产生重复词条，备注仍存在。
- **AC-09** Given 用户卸载当前模型，When 再发起翻译，Then UI 显示下载/选择模型引导，其他词典功能可用。
- **AC-10** Given 复杂 Markdown 含 ```code```、`{name}`、URL、数字，When 开启结构保护翻译，Then 关键 token 完全一致，否则显式标错。

浏览器：Chrome、Edge、Safari；文档：Word、可选中文本 PDF、扫描 PDF；聊天：Teams、微信桌面版；编辑器：VS Code；屏幕：单屏、双屏、DPI 100/150/200%、Retina；电源：充电/电池；权限：全部允许/部分拒绝/随后撤销；网络：在线/弱网/断网；模型：未安装/下载中/正常/校验失败/运行中崩溃。

| EP-07 OCR | 截屏层、Vision、WinRT、文本编辑 | 双系统无联网 OCR |
| EP-08 Speech | 系统 TTS、IPA 词条显示、发音控件 | 无资源和多语种降级可解释 |
| EP-09 Wordbook | 收藏/历史/备注/清除/导出 | 数据迁移与私密模式测试 |
| EP-10 Release | 签名、公证、自动更新、许可证页、卸载 | 安全发布、可回滚 |

## 17. 风险登记与缓解策略

| 风险 | 影响 | 缓解措施 | 优先级 |
|---|---|---|---|
| Hy-MT2 在 Intel Mac/低内存上速度过慢 | 浮层等待、体验差 | 首版选 Q4；基准测试；字典即时返回；自愿禁用 AI | 高 |
| 1.25-bit STQ 内核兼容不成熟 | 模型无法加载或输出异常 | 不作为 MVP 依赖；锁定已测试运行时 | 高 |
| 跨应用划词和权限不一致 | 功能无法可靠使用 | 双路径取词、显式提示、手动粘贴回退 | 高 |
| 词库许可或例句质量问题 | 不能发布、内容错误 | 建数据来源台账、先法务清理和小规模可用词库 | 高 |
| OCR 排版错位/中文混排 | 译文不可信 | OCR 可编辑、预览原文、不做无提示自动替换 | 中 |
| 模型内存/负载过高 | 系统卡顿、崩溃 | 限并发、卸载/降级、OOM 恢复 | 高 |
| 下载包大、弱网失败 | 初次转化率低 | 首包小、断点续传、可不下载模型使用 | 中 |
| 用户以为数据被云上传 | 信任受损 | 数据流可视化、网络隔离测试、默认零上传 | 中 |
| macOS 签名/公证及安装成本 | 分发困难 | 提前配置证书与自动构建 | 中 |

## 18. 发布计划与版本边界

**Alpha / v0.1：** 主窗口+离线词典+Hy-MT2 Q4 翻译页+模型下载，仅开发者使用。**Beta / v0.5：** Windows/macOS 划词、浮层、OCR、生词本、权限指南。**v1.0：** 签名发行、多设备兼容、数据许可声明、隐私和稳定性测试。**v1.1：** 7B 可选、术语表、复习、Markdown 保护。**v2.0：** 云端自部署可选、同步和插件生态（如果实际需求验证成立）。

**Go/No-Go：** 在至少 Windows x64、Apple Silicon、Intel Mac 三类设备上完成安装、查词、翻译、划词、OCR；P0 验收全部通过；至少 24 小时稳定性测试；模型和词库许可可追溯；无默认上传；无严重隐私或崩溃缺陷。任何一项不满足则不进入 v1 公测。

## 19. 尚待验证的问题（带默认决策）

1. **翻译速度是否足以支持“即划即译”？** 默认首出结构化词典结果，AI 译文异步加载；M0 实测后决定是否需要预热模型。
2. **中文词典来源是否具有可分发许可证？** 没有明确授权的资源一律不入包；先用英文释义+合法中英基础词表完成 MVP。
3. **是否长期支持 Intel Mac？** v1 按 x64 发布和 CPU 回退计划；若性能测试失败，保留词典和 OCR 功能并在 UI 标注 AI 性能限制。
4. **是否要主动弹出划词图标？** 默认关闭，以避免打扰和持续感知选区；v1.1 再加可选开关。
5. **云端推理、跨设备生词同步是否必要？** v1 不引入帐号或服务器；通过内测需求再评估。
6. **是否允许更换其他翻译模型？** 内部 `TranslationProvider` 抽象预留，但 v1 UI 只支持官方列出的 Hy-MT2 变体，防止测试矩阵膨胀。

## 20. 开发启动顺序与最终建议

开发顺序应是 **PoC 优先，而不是先画大而全的 UI**：首先分别在 Windows 与两类 Mac 上验证 Q4 模型能否稳定加载和翻译；随后验证划词与截图权限；第三步锁定合法词典数据；最后才进入 Tauri 页面、悬浮卡和生词本开发。避免把“翻译模型”当作“词库”，也不要把 440MB 模型体积当作 440MB 系统内存需求。

对于 8GB Apple Silicon Mac，建议默认 1.8B Q4 并提供“节能 / 关闭自动翻译”。对于 Windows 大内存主机可允许安装 7B 作为高质量模式。所有性能与体验结论必须通过版本、设备、样本可复现的实验确认。
